# Ревью кода

## Быстрый старт

При ревью изменений кода сфокусируйся на:

1. Корректности и возможных регрессиях.
2. Безопасности и рисках для данных.
3. Поддерживаемости и читаемости.
4. Покрытии тестами и валидации.

## Чеклист ревью

- [ ] Логика корректна для happy path и крайних случаев.
- [ ] Обработка ошибок явная и не скрывает сбои.
- [ ] Нет очевидных рисков безопасности (инъекции, обход авторизации, утечки секретов).
- [ ] Публичные контракты сохранены (форма API, схемы, совместимость).
- [ ] Изменения минимальны и ограничены рамками задачи.
- [ ] Тесты покрывают ключевые изменения поведения и failure-сценарии.

## Формат замечаний

Используй такой формат:

- Critical: обязательно исправить до merge.
- Warning: важный риск, желательно исправить.
- Suggestion: улучшение, опционально.

Для каждого замечания укажи:

1. Что именно не так.
2. Почему это важно.
3. Конкретный вариант исправления.

## Шаблон ответа

```markdown
## Замечания
- Critical: <проблема и влияние>
- Warning: <проблема и влияние>
- Suggestion: <улучшение>

## Открытые вопросы
- <вопрос или допущение>

## Краткий итог
- <одной строкой общее качество/риски>
```
